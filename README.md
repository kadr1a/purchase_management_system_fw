# Система управления закупками

## Назначение

Приложение для учёта товаров, поставщиков, заявок на закупку и заказов с консольным интерфейсом и веб-интерфейсом на Django. В ПР3 проект из ПР2 переработан с использованием объектно-ориентированной модели: основные сущности представлены классами, а коллекции содержат экземпляры этих классов.

## Целевая аудитория

Сотрудники организации, которые формируют заявки на закупку, согласуют их и оформляют заказы поставщикам.

## Основные классы

- **Product** (`models/product.py`) — товар: `id`, `name`, `price`, `description`; `__str__()` формирует строковое представление.
- **Supplier** (`models/supplier.py`) — поставщик: `id`, `name`, `contact`, `rating`; `__str__()` формирует строковое представление.
- **Application** (`models/application.py`) — заявка: `id`, `purpose`, `product_items`, `status`. Методы `add_product()`, `calculate_total()`, `approve()`, `__str__()`. В позициях заявки хранятся ссылки на объекты `Product` и количество.
- **PurchaseOrder** (`models/purchase_order.py`) — заказ: `id`, `application`, `supplier`, `total`, `status`. Хранит ссылки на объекты `Application` и `Supplier`; метод `cancel()` меняет статус заказа, `__str__()` возвращает описание.

## Взаимодействие объектов

Заявка содержит товары как пары `(Product, quantity)`. Заказ связан с согласованной заявкой и поставщиком через ссылки на соответствующие объекты. При создании заказа статус заявки меняется на «Заказ оформлен». При отмене заказа сам объект остаётся в коллекции, а его статус меняется на «Отменён».

## Основные возможности

- добавление, поиск, фильтрация и сортировка товаров;
- добавление и сортировка поставщиков;
- создание заявки, добавление товаров и расчёт общей суммы;
- согласование непустой заявки;
- создание заказа по согласованной заявке;
- отмена оформленного заказа;
- загрузка и сохранение данных в JSON;
- обработка некорректного ввода и ошибок операций.

## Хранение данных

JSON остаётся форматом постоянного хранения. В `products.json` сохраняются поля товара, в `suppliers.json` — поля поставщика. В заявках позиции содержат `product_id` и `quantity`. В заказах сохраняются `application_id` и `supplier_id`.

При запуске `storage.load_data()` сначала восстанавливает товары и поставщиков, затем заявки, а после них заказы. Идентификаторы используются для восстановления ссылок между объектами. При сохранении `storage.save_data()` преобразует объекты обратно в JSON-совместимые словари. Если ссылка в JSON указывает на отсутствующий объект, загрузка завершается понятной ошибкой.

## Установка и запуск

Требуется Python 3.10 или новее. Команды выполняются из корневой папки проекта.

```bash
python -m venv .venv
```

Windows: ` .venv\Scripts\activate `

macOS/Linux: `source .venv/bin/activate`

Установка зависимостей и запуск:

```bash
pip install -r requirements.txt
python main.py
```

## Веб-интерфейс Django (ПР5–ПР6)

Веб-часть проекта реализована на Django и разделена на приложения:
- `homepage` — главная страница;
- `products_web` — каталог товаров и карточки товаров;
- `suppliers_web` — список поставщиков и карточки поставщиков;
- `applications_web` — заявки на закупку и их состав;
- `orders_web` — заказы поставщикам.

HTML формируется системой шаблонов Django (Django Template Language), а не Python-строками во view-функциях. Общая структура находится в `templates/base.html`; дочерние страницы используют `{% extends %}` и блоки `{% block %}`. Повторяющаяся навигация, карточки сущностей и другие элементы вынесены в подключаемые шаблоны через `{% include %}`. Представления подготавливают контекст и вызывают `render()`. В шаблонах используются циклы, условия, фильтры `length`, `default` и `floatformat`.

Для каждого Django-приложения заданы `app_name` и именованные URL-маршруты. Ссылки в HTML формируются тегом `{% url %}` с пространствами имён (`homepage:index`, `products:list`, `products:detail` и т. д.). Статические ресурсы приложения `homepage` включают собственный CSS, логотип PNG и JavaScript для отображения текущего года в подвале.

### Основные веб-страницы
- `/` — главная страница со статистикой разделов;
- `/products/` и `/products/<id>/` — каталог и карточка товара;
- `/suppliers/` и `/suppliers/<id>/` — поставщики и карточка поставщика;
- `/applications/` и `/applications/<id>/` — заявки и состав заявки;
- `/orders/` и `/orders/<id>/` — заказы и карточка заказа.

Для отсутствующих объектов отображается соответствующее сообщение с HTTP-статусом 404. Общая ошибка неизвестного URL также обрабатывается отдельным шаблоном `templates/404.html`.

### Хранение данных и ограничения текущего этапа
Данные продолжают храниться в JSON-файлах каталога `data/`. Используются исходные Python-классы `Product`, `Supplier`, `Application` и `PurchaseOrder`, а загрузка и восстановление связей выполняются существующей функцией `storage.load_data()`. Django ORM, база данных приложения и Django-формы на данном этапе не внедрялись; это задачи следующих практических работ. Консольная версия проекта сохранена.
