# Система управления закупками

## Назначение

Консольное приложение для учёта товаров, поставщиков, заявок на закупку и заказов. В ПР3 проект из ПР2 переработан с использованием объектно-ориентированной модели: основные сущности представлены классами, а коллекции содержат экземпляры этих классов.

## Целевая аудитория

Сотрудники организации, которые формируют заявки на закупку, согласуют их и оформляют заказы поставщикам.

## Основные классы

- **Product** (`models/product.py`) — товар: `id`, `name`, `price`, `description`; `__str__()` формирует строковое представление.
- **Supplier** (`models/supplier.py`) — поставщик: `id`, `name`, `contact`, `rating`; `__str__()` формирует строковое представление.
- **Application** (`models/application.py`) — заявка: `id`, `purpose`, `product_items`, `status`. Методы `add_product()`, `calculate_total()`, `approve()`, `__str__()`. В позициях заявки хранятся ссылки на объекты `Product` и количество.
- **PurchaseOrder** (`models/purchase_order.py`) — заказ: `id`, `application`, `supplier`, `total`, `status`. Хранит ссылки на объекты `Application` и `Supplier`; метод `cancel()` меняет статус заказа, `__str__()` возвращает описание.

## Взаимодействие объектов

Заявка содержит товары как пары `(Product, quantity)`. Заказ связан с согласованной заявкой и поставщиком через ссылки на соответствующие объекты. При создании заказа статус заявки меняется на «Заказ оформлен». При отмене заказа сам объект остаётся в коллекции, а его статус меняется на «Отменён».

## Основные возможности

- добавление, поиск, фильтрация и сортировка товаров;
- добавление и сортировка поставщиков;
- создание заявки, добавление товаров и расчёт общей суммы;
- согласование непустой заявки;
- создание заказа по согласованной заявке;
- отмена оформленного заказа;
- загрузка и сохранение данных в JSON;
- обработка некорректного ввода и ошибок операций.

## Хранение данных

JSON остаётся форматом постоянного хранения. В `products.json` сохраняются поля товара, в `suppliers.json` — поля поставщика. В заявках позиции содержат `product_id` и `quantity`. В заказах сохраняются `application_id` и `supplier_id`.

При запуске `storage.load_data()` сначала восстанавливает товары и поставщиков, затем заявки, а после них заказы. Идентификаторы используются для восстановления ссылок между объектами. При сохранении `storage.save_data()` преобразует объекты обратно в JSON-совместимые словари. Если ссылка в JSON указывает на отсутствующий объект, загрузка завершается понятной ошибкой.

## Установка и запуск

Требуется Python 3.10 или новее. Команды выполняются из корневой папки проекта.

```bash
python -m venv .venv
```

Windows: ` .venv\Scripts\activate `

macOS/Linux: `source .venv/bin/activate`

Установка зависимостей и запуск:

```bash
pip install -r requirements.txt
python main.py
```
